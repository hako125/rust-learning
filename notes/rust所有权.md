# rust所有权

> 来源：https://rust-book.cs.brown.edu/ch04-01-what-is-ownership.html
> 核心叙事：**安全 = 没有未定义行为（UB） → 所有权是为了在编译期消灭内存类 UB**。

## 安全就是没有未定义行为

**安全 = 程序执行期间永远不会出现未定义行为（Undefined Behavior, UB）。**

> UB 最可怕之处：可能不崩溃，而是静默返回错误数据，或被利用做攻击（底层系统 70% 的安全漏洞源于内存破坏）。

**Rust 的两个目标**：
1. 消灭 UB（首要）
2. **在编译期**消灭 UB（避免生产 bug + 减少运行时检查提升性能）

## 存放在堆中的数据——Boxes

问题：复制一些数据可能会消耗大量内存：

比如：大数组如果将值放在栈帧中，表达式读变量时会复制这个大数组中的值，非常耗内存。

![](assets/rust%E6%89%80%E6%9C%89%E6%9D%83-%E5%8E%9F%E7%90%86/IMG-20261026005556756.png)

为了不复制数据的情况下转移数据的访问权，Rust使用了指针（Pointer），指针描述内存中某个位置（地址），指向的值叫做Pointee。

创建指针的常见方式是在堆上分配内存（堆与栈帧无关，不与栈绑定）

Rust提供了一种名为`Box`的结构，用于将数据存放于堆上。例如：下面用Box::new将大数组存放在堆中，然后将a定义为一个指向大数组的指针

![](assets/rust%E6%89%80%E6%9C%89%E6%9D%83-%E5%8E%9F%E7%90%86/IMG-20261026005913163.png)

**移动：** 可以看到上面将指针a的指向交给b后，a变灰了，这是因为在Rust中，发生了所有权移动，导致变量a失效了。
## Rust 不允许手动管理内存

假设 Rust 允许 `free()`：

```rust
let b = Box::new([0; 1_000_000]);
free(b);        // 手动释放
// 此刻 b 是悬垂指针，但仍"安全"—— 拥有无效指针本身不违规
println!("{}", b[0]);   // ❌ UB：通过悬垂指针读内存
```

结论：**手动 free 极易产生 UB，Rust 直接禁止。**

## Box 的所有权拥有者负责管理Box的内存释放（最关键的一段）

先给出一个"几乎正确"的原则：

> **（几乎正确）** 若变量绑定了一个 Box，当 Rust 释放该变量的栈帧时，释放其堆内存。

反例：

```rust
let a = Box::new([0; 1_000_000]);
let b = a;
// 栈帧结束时，会按 a 和 b 各 free 一次 → double free ❌
```

修正为正确答案：

> **（完全正确）Box 释放原则：若变量 *拥有* 一个 Box，当 Rust 释放该变量的栈帧时，才释放其堆内存。**

引入所有权后：`let b = a;` 是**移动（move）所有权**，只有 `b` 拥有，所以只 free 一次。

##  集合内部用的就是 Box

`Vec`、`String`、`HashMap` 都用 box-like 的堆分配来存不定长元素。

![](assets/rust%E6%89%80%E6%9C%89%E6%9D%83-%E5%8E%9F%E7%90%86/IMG-20261026011330823.png)

**关键点**：`first` 在 `push_str` 之后有可能变成**指向已释放内存的悬垂指针**（如果触发String的扩容机制的话，会将原来的Heap内存销毁，将新的String内容添加到新的Heap内存上），但由于所有权移动导致first失效，无法访问这个悬垂指针，从而规避了后续UB代码的出现。

## 不能使用已 move 的变量

![](assets/Pasted%20image%2020261026015040.png)

> **Moved heap data principle**：若变量 x 把堆数据的所有权 move 给了 y，则 **x 之后不能再用**。

## Clone 可以避免 move

```rust
let first = String::from("Ferris");
let first_clone = first.clone();       // 深拷贝：新堆分配，复制 "Ferris"
let full = add_suffix(first_clone);    // first_clone 被 move 并失效
println!("{full}, originally {first}"); // ✅ first 未动，仍可用
```

`move` = 浅拷贝指针 + 作废原变量；`clone` = 深拷贝堆数据，两份独立。

## 8. 总结（原文 Summary 四条）

所有权本质是**堆管理**的纪律：

1. **所有堆数据必须恰好由一个变量拥有**
2. **所有者离开作用域时，Rust 释放该堆数据（只释放一次）**
3. **所有权通过 move 转移**（发生在赋值和函数调用时）
4. **堆数据只能通过当前所有者访问，不能通过旧所有者访问**

## 9. 一句话记忆

**栈帧自动管理 → 堆数据必须有唯一所有者 → 所有者死去才 free → move 让旧所有者失效。**
