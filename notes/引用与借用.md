所有权在避免内存问题的同时也造成了很多不便，比如说下面m1, m2的读取。

## 地址，指针，引用与借用

- **地址**：无论一个数据存放在堆还是栈，它都对应一个内存编号，这个编号就是这个数据的地址。
- **指针**：指针是一种**数据类型**，它表示对一个数据在内存中位置的指向，指针宏观来看就是指向数据的地址，但包含了指向数据的类型等更多信息。
- **引用**：引用也是一种指针，但额外受到Rust借用规则、有效性和生命周期等约束。

`&` 引用运算符可以用来获取数据的地址。

```rust
fn test_reference() {

    let x = 233;

    let x = &x;  // 创建一个引用

    let p: *const i32 = x as *const i32;  // 将引用转换为指针

    println!("p的地址：{:p}", p);   //  0x2efcf7f914

    println!("x的地址：{:p}", x);   //  0x2efcf7f914，引用和指针一样指向x变量所在的地址

}
```

**传递数据的引用不会引起数据所有权的移动**，这种机制就是Rust的借用机制。


## 解引用

`*` 运算符可以用来解引用，可以用来访问指针指向的内存地址的具体数据。

![](notes/assets/引用与借用/引用与借用-20261027180932993.png)

如果想通过解引用来将一个数据交给另一个变量也是要考虑所有权的转移的。

```rust
// 测试解引用

fn test_dereference() {

    let x = Box::new("2233");

    let y = &x;

    // let z = *y;  // 不行 这企图于把x的所有权通过y转移给了z， 而y是没有数据的所有权的。

    let z = **y; // 这样可以，因为拿到的是"2233"这一个Copy数据, 这里可以直接值传递。

}
```

**隐式解引用**

有时候我们会给一个值套好多层引用， 为了方便使用 `.` 运算符会自动解引用或者自动引用，例如下面的情况：

```rust
let x: Box<i32> = Box::new(-1); 
let x_abs1 = i32::abs(*x); // explicit dereference 
let x_abs2 = x.abs(); // implicit dereference 
assert_eq!(x_abs1, x_abs2); 

let r: &Box<i32> = &x; 
let r_abs1 = i32::abs(**r); // explicit dereference (twice) 
let r_abs2 = r.abs(); // implicit dereference (twice) 
assert_eq!(r_abs1, r_abs2); 

let s = String::from("Hello"); 
let s_len1 = str::len(&s); // explicit reference 
let s_len2 = s.len(); // implicit reference assert_eq!(s_len1, s_len2);
```
